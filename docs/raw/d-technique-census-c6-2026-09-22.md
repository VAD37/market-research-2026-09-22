## (1) Mechanism — how it works, per source

| Source | Raw path | Mechanism as the source describes it |
|---|---|---|
| Greshake et al., foundational IPI paper | `d-injection-greshake-foundational-ipi-2026-09-22.md` | Names "Indirect Prompt Injection": adversaries "remotely... exploit LLM-integrated applications by strategically injecting prompts into data likely to be retrieved" — LLM-integrated apps "blur the line between data and instructions" |
| Pfrommer et al. (EMNLP 2024) | `d-injection-pfrommer-ranking-manipulation-2026-09-22.md` | Prompt injections alter "the ranking order of sources referenced by conversational search engines"; a tree-of-attacks jailbreaking technique "reliably promotes low-ranked products" |
| Nestaas, Debenedetti, Tramèr | `d-injection-nestaas-adversarial-seo-2026-09-22.md` | Names "Preference Manipulation Attacks": "carefully crafted website content or plugin documentations can trick an LLM to promote the attacker products and discredit competitors" |
| PoisonedRAG (Zou et al., USENIX Security 2025) | `d-injection-poisonedrag-2026-09-22.md` | "Knowledge corruption attack": attacker "inject[s] a few malicious texts into the knowledge database of a RAG system to induce an LLM to generate an attacker-chosen target answer for an attacker-chosen target question" |
| Choi et al. — Agent Data Injection | `d-injection-choi-agent-data-injection-2026-09-22.md` | Names a new IPI sub-class, "agent data injection (ADI)": "injects malicious data disguised as trusted data, such as security-critical metadata... or agent context data," distinct from instruction injection |
| Narisetty et al. — out-of-band defenses | `d-injection-narisetty-oob-defenses-2026-09-22.md` | Not an attack-mechanism paper; documents the defense-side mechanism class — "enforce security outside the model with a deterministic policy that mediates the agent's actions" (capabilities, information-flow labels, reference monitors) |
| Chen et al. — IPI-proxy | `d-injection-chen-ipi-proxy-2026-09-22.md` | "Adversaries can... influence [agents] by embedding hidden instructions in the HTML pages... domains serve"; names three embedding techniques — "HTML comment, invisible CSS, or LLM-generated semantic prose" — and six HTML insertion points |
| Brave — Comet disclosure | `d-injection-brave-comet-disclosure-2026-09-22.md` | "Comet feeds a part of the webpage directly to its LLM without distinguishing between the user's instructions and untrusted content from the webpage" — hidden instructions behind a Reddit spoiler tag |
| OpenAI — Operator system card | `d-injection-openai-operator-systemcard-2026-09-22.md` | "Vulnerabilities like prompt injection attacks where malicious instructions in third-party websites can mislead the model away from the user's intended actions" |
| Google — mitigating prompt injection | `d-injection-google-mitigating-pi-2026-09-22.md` | "Hidden malicious instructions within external data sources. These may include emails, documents, or calendar invites that instruct AI to exfiltrate user data or execute other rogue actions" |
| Anthropic — computer use docs | `d-injection-anthropic-computeruse-docs-2026-09-22.md` | "Claude will follow commands found in content even when they conflict with your instructions. For example, instructions on webpages or contained in images might override your instructions" |
| Yin et al. (SIGIR 2026) | `d-injection-yin-llm-rankers-2026-09-22.md` | "Simple prompt injections embedded within a candidate document (i.e., jailbreak prompt attacks) can significantly alter an LLM's ranking decisions"; names two variants, "decision objective hijacking and decision criteria hijacking" |
| Microsoft — Copilot Bounty scope | `d-injection-microsoft-copilot-bounty-2026-09-22.md` | Not a mechanism description — a scope clause only (see table 4) |

Mechanism classes present across these thirteen sources, named as the sources name them: (a) **instruction injection into retrieved/indexed text** — Greshake, Pfrommer, Nestaas, Google, Anthropic, OpenAI, Yin, Brave/Comet; (b) **knowledge-base / RAG corpus poisoning** — PoisonedRAG; (c) **agent data injection (trusted-metadata disguise, not instruction text)** — Choi; (d) **out-of-band / deterministic-policy defense** (the counter-mechanism) — Narisetty; (e) **payload-delivery tooling for red-teaming the retrieval surface itself** (HTML comment / invisible CSS / generated prose, at named insertion points) — Chen.
