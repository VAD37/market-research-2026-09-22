## Caveats

- This cluster's four tables answer Pass 5's questions for "structured data and llms.txt-style signalling" only; they do not score H5, H13, or S12 — scoring against `docs/method/hypotheses.md` decision conditions is Pass 9's task, against this file and the raw pulls it cites.
- The Borysenko study (table 3, tier 4) and the Volpini study (table 3, tier 5) measure two different things that both bear on H5: whether an engine **fetches** the llms.txt artefact at all (Borysenko: no, across 6 assistants), and whether structured/agent-readable formatting **improves retrieval accuracy inside a controlled RAG pipeline** the researchers built (Volpini: yes, substantially). Neither paper measures whether a priority-1/2 engine's own **production** answer to a real user prompt changes because a target page added llms.txt or schema.org markup — that specific before/after test was not found published by any source in this cluster.
- S12 in this cluster is two small, non-random brand samples (5 beauty domains, 10 B2B SaaS domains), both already landed pre-existing raw, cited but not re-pulled; this cluster did not add a third vertical (high-CPA regulated) sample of its own.
- No test was run against any third-party production answer surface, brand, or engine by this task, per the Lane D hard constraint in `docs/method/plan.md`. All measured-by-us pulls in this cluster are passive HTTP checks of static files (`/llms.txt` presence) against domains the market studies (brand samples, engine operators' own developer/documentation domains), never against a chat/answer surface itself, and no artefact was published, edited, or tested anywhere.
